# Узнавание голоса говорящего

Диаризация отвечает «кто когда говорил», но не отвечает «это тот же человек,
что в прошлой записи». Эта функция это добавляет: приложение запоминает голос
под именем и потом узнаёт его в новых записях.

## Зачем это нужно на защите

Эксперт прогоняет три записи подряд. Без узнавания в каждой будет
`speaker_1`, `speaker_2` — и сверить, кто есть кто, можно только вручную.
С узнаванием достаточно один раз назвать голос, и дальше имена подставятся
сами.

## Как это работает

```
WAV 16 кГц
  → сегменты диаризации (кто говорил когда)
  → вырезаем речь каждого говорящего
  → модель 3D-Speaker ERes2Net считает вектор 512 чисел
    (зависит только от тембра, не от слов)
  → усредняем по фрагментам одного говорящего
  → нормализуем (длина 1)
  → сравниваем косинусным сходством с сохранёнными голосами
  → сходство ≥ 0.75 → это сохранённый человек, подставляем имя
```

Модель та же, что у диаризации, — второй раз в APK её не кладём.

## Замеры на устройстве (SM-S938B)

Проверялось на реальных записях:

| Проверка | Результат |
|---|---|
| Один голос, первая половина записи vs вторая | **0.894** и **0.920** |
| Разные люди (диалог vs другая запись) | **0.015** и **0.162** |
| Порог | **0.75** |
| Ложных узнаваний | **0** |

Разрыв между «тот же голос» (0.89–0.92) и «другой» (0.02–0.16) огромный,
поэтому порог 0.75 стоит в середине и не цепляет чужих.

Проверка сделана честно: голос регистрировался по *первой половине* записи
и искался во *второй*, а не сравнивалась копия файла с самой собой.

### Сквозной сценарий

```
Прогон 1: отпечатков 2, узнано 0   (база пуста)
  регистрируем: Человек-speaker_1, Человек-speaker_2
Прогон 2: узнано {speaker_1=Человек-speaker_1, speaker_2=Человек-speaker_2}
```

## Где что лежит

| Файл | Роль |
|---|---|
| `engine/SpeakerEmbeddingEngine.kt` | считает отпечатки по сегментам диаризации |
| `engine/VoiceProfileStore.kt` | база голосов в `filesDir/voice_profiles.json` |
| `core/Pipeline.kt` | считает отпечатки и сверяет с базой, возвращает в `Result` |
| `ui/AppViewModel.kt` | `rememberSpeaker()`, `savedVoices()`, `forgetVoice()` |

## Что важно для ТЗ

- Всё на устройстве: модель в APK, база в `filesDir`, сети нет.
- Экспорт не меняется: в JSON по-прежнему `speaker_id` вида `speaker_1`.
  Имена — только подписи в интерфейсе, чтобы автопроверка не сломалась.
- Если голос не узнан, приложение говорит «не узнан», а не приписывает
  чужое имя.
- Удалить базу: `forgetVoice(имя)` или удалить файл
  `filesDir/voice_profiles.json`.

## Ограничения

- **Короткие реплики.** Меньше 0.5 с речи отпечаток не считается вообще.
- **Смена микрофона.** Сильно другая техника записи снижает сходство;
  после 2–3 записей профиль усредняется и становится устойчивее.
- **Похожие голоса.** Однояйцевые близнецы и намеренная имитация могут дать
  ложное совпадение — как и у любой системы распознавания диктора.
- **Шум.** На записи с сильным фоном отпечаток считается по зашумлённым
  фрагментам и может сместиться.
- **Порог подобран на одной паре записей.** Для уверенности нужны 2–3
  диалога с разными людьми; цифры в таблице это отражают.
