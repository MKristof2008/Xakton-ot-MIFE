# Промпты капитана: средний уровень и Ultra Pro Max

> Источник: сообщение капитана. Эти пункты не дают отдельных баллов —
> они улучшают метрики из критериев. Приоритет по баллам:
> VAD (WER 40, RTF 10) → спикеры (DER 25) → прогресс/плеер (UX 10) →
> пунктуация LLM → шумоподавление (только после A/B) → одновременная речь (последняя).

## Общие правила (обязательны для каждой фичи)
1. Фича включается флагом в настройках, по умолчанию выкл.
2. До включения: замер baseline на наборе из 3 записей (Release, 3 повтора,
   медиана): WER, DER, RTF, пик RAM.
3. После: те же замеры. Фича остаётся включённой только если WER, DER, RTF
   не ухудшились (допуск: WER +0.5 п.п., RTF +10%) либо улучшился UX без
   ухудшения метрик.
4. Один коммит на фичу: сообщение + таблица «до/после» в docs/runs/.
5. Если данных нет — пишем «нет данных». Цифры не выдумываем.
6. Перед фичей проверяем по коду/документации сборки, что компонент
   (Silero VAD, GTCRN, NNAPI) реально есть в сборке — «если есть в сборке».

## Средний уровень (по порядку, следующая задача — после замеров предыдущей)
- A. Фильтрация пауз/неречевых фрагментов: Silero VAD (в sherpa-onnx, если есть),
  в ASR только речевые сегменты, таймкоды пересчитывать относительно исходного
  файла. Проверить, что start_ms/end_ms не съезжают.
- B. Устойчивые спикеры: сглаживание меток диаризации (мин. длина сегмента,
  склейка соседних кусков одного спикера, порог кластеризации), DER на 2+ спикерах.
- C. Пунктуация и регистр локальной LLM (0.5–1.5B GGUF): менять слова запрещено,
  только знаки и заглавные. Контроль: после нормализации (нижний регистр, без
  пунктуации, ё=е) текст до/после LLM совпадает; иначе откат. По чанкам.
- D. Прогресс: этапы + процент, фоновая обработка (foreground service), отмена.
- E. Плеер: воспроизведение, тап по реплике → переход к start_ms, подсветка.
- F. Предобработка аудио: нормализация громкости, ресемпл 16 кГц моно.
  Шумоподавление (GTCRN, если есть) — только авто-включение по SNR + A/B на
  шумной и чистой записях.

## Ultra Pro Max (только после закрытия среднего уровня, по убыванию отдачи)
Сначала оценка «выигрыш в баллах / трудоёмкость»; выигрыш неясен — не делаем.
- A. Оптимизация RAM: пик по этапам, выгрузка моделей после этапа, стриминг
  кусками; проверка на записи 10+ мин без OOM.
- B. Ускорение инференса: потоки, int8-квантизация, XNNPACK/NNAPI (если есть;
  NNAPI бывает медленнее CPU — не включать вслепую). Каждое — замером на телефоне.
- C. Короткие реплики/перебивания: мин. длина сегмента в VAD/диаризации,
  DER и число потерянных коротких реплик («да», «угу») на записи с перебиваниями.
- D. Шумные записи: A/B шумоподавления; оставить только если WER на шумной лучше,
  а на чистой не хуже.
- E. Тембр/манера речи: выбор эмбеддинг-модели диаризации и порог кластеризации
  на разных голосах.
- F. Редактирование фрагментов: правка текста, смена speaker_id, повторная
  обработка выбранного диапазона.
- G. Одновременная речь: только если A–F закрыты. Допустимо честно записать
  ограничение в «Описание ограничений решения».

## Защита
Каждый должен уметь объяснить, зачем нужна каждая включённая фича и что
показали замеры. Не включаем то, чего сами не понимаем.

## Статус у нас (feature/ml)
- Зависит от бенчмарка: сначала замер Release (baseline), потом фичи A→F.
- Наша зона: VAD (A), спикеры (B), пунктуация LLM (C), предобработка (F),
  Ultra A–E. Прогресс (D), плеер (E), редактирование (F) — зона фронтенда,
  мы даём данные через TranscriptionEngine (Stage/Progress, cancel).
