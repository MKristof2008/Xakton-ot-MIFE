# Архитектура решения

## Контекст

Задача хакатона — локальное преобразование аудиозаписи разговора в структурированную
расшифровку с разделением говорящих. Жёсткое требование: все вычисления на устройстве,
без облачных API и без передачи аудио наружу.

Решение — Android-приложение на Kotlin с Jetpack Compose. Модели работают в процессе
приложения, сеть не используется.

## Основные технические решения

**1. Контракты вместо прямой связи модулей.**
Каждый движок реализует интерфейс (`AsrEngine`, `DiarizationEngine`, `LlmEngine`).
Это позволяет вести разработку параллельно и менять модель, не трогая остальной код.

**2. Сшивка по максимальному пересечению.**
Результаты распознавания и диаризации не совпадают по границам. Каждый сегмент ASR
получает говорящего с наибольшим перекрытием по времени. Если перекрытия нет —
идентификатор `speaker_unknown`, а не догадка.

**3. Заглушки как часть архитектуры.**
В debug-сборке движки заменяются заглушками. Приложение работает без моделей и без сети:
интерфейс и экспорт тестируются независимо от готовности моделей. Это прямо предписано ТЗ
(«пока модуль не готов — работаем на заглушках»).

**4. Отсутствие разрешения INTERNET.**
Приложение не запрашивает доступ к сети. Это не декларация, а проверяемый факт:
`aapt2 dump permissions` на собранном APK не показывает `INTERNET`.

**5. Метрики встроены в код, а не считаются вручную.**
WER, DER и RTF реализованы в `core/Metrics.kt` без внешних зависимостей, покрыты
юнит-тестами. Результаты замеров попадают в `docs/TEST_RESULTS.md`.

## Зависимости

| Слой | Библиотека | Назначение |
|---|---|---|
| UI | Jetpack Compose (BOM 2024.06) | интерфейс |
| UI | Material 3 | компоненты |
| Состояние | Lifecycle ViewModel + StateFlow | управление состоянием |
| Асинхронность | Kotlin Coroutines | обработка в фоне |
| JSON | org.json | сериализация по схеме ТЗ |
| Тесты | JUnit 4 | проверка ядра |

Модели (добавляются при подключении):
- распознавание речи — `whisper.cpp` (ggml), модель `whisper-small`;
- диаризация — `pyannote/speaker-diarization-3.1` в ONNX или эмбеддинги `speechbrain`;
- языковая модель — `llama.cpp` + `Gemma-2-2B` (Q4).

## Безопасность и приватность

- аудио не покидает устройство: нет разрешения на интернет, нет сетевых вызовов;
- файлы обрабатываются во внутреннем кэше приложения;
- экспорт выполняется через системный диалог «Поделиться» — пользователь сам выбирает,
  куда отправить результат;
- секретов и ключей в приложении нет: внешние сервисы не используются.

## Ограничения архитектуры

- Модели загружаются в память целиком: на устройствах с малым объёмом RAM возможна
  последовательная загрузка (ASR выгружается перед LLM).
- Диаризация по акустике требует отдельной модели; угадывание имён по тексту
  (как в Python-прототипе) задачу DER не решает.
- Точность зависит от качества записи: шум и перебивания снижают WER и DER.
