## 1. Общие сведения о проекте

### 1.1. Формулировка задания

Согласно официальной презентации организаторов, требуется разработать Android-приложение,
которое локально преобразует аудиозаписи разговоров в текст, автоматически определяя
говорящих и разделяя их реплики. Результат должен быть доступен для просмотра
и экспорта в файл. Все этапы обработки выполняются на устройстве.

### 1.2. Обязательные требования

| № | Требование |
|---|---|
| 1 | Работа под управлением Android OS |
| 2 | Использование локальной языковой модели |
| 3 | Импорт аудиозаписи из памяти устройства |
| 4 | Преобразование речи в текст |
| 5 | Автоматическое определение и разделение говорящих |
| 6 | Формирование временных меток для реплик |
| 7 | Отображение полученной расшифровки |
| 8 | Экспорт результата в файл |

### 1.3. Жёсткие ограничения

Нарушение перечисленного влечёт дисквалификацию решения.

| № | Запрет | Статус соблюдения |
|---|---|---|
| 1 | Передача аудиозаписей внешним сервисам | Соблюдается |
| 2 | Облачные API для транскрибации, диаризации, обработки текста | Соблюдается |
| 3 | Вычисления на удалённом сервере или компьютере | Соблюдается |
| 4 | Подмена работы модели заранее подготовленной расшифровкой | **Требует устранения** (п. 6.2) |

Дополнительно разрешено: использование готовых моделей и библиотек; размещение моделей
на устройстве к моменту проверки.

### 4.2. Влияние языковой модели на точность

Замер на контрольной записи `dialog_2spk.wav` (79,8 с, 8 реплик, 2 говорящих).
Модель Qwen2.5-1.5B-Instruct Q4_K_M, движок llama.cpp.

| Режим обработки | WER | Изменение |
|---|---|---|
| Распознавание без языковой модели | 0,1443 | — |

**Вывод:** полная правка текста языковой моделью снижает точность, поскольку модель
допускает смысловые замены. Роль языковой модели ограничена восстановлением пунктуации
и регистра, при котором показатели точности не изменяются.

### 5.1. Отсутствие доступа к сети

Выполнена инструментальная проверка собранного пакета.

```
aapt2 dump permissions app-release-unsigned.apk
```

Результат: разрешение `INTERNET` отсутствует. Обнаруженные разрешения:
`RECORD_AUDIO`, `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_DATA_SYNC`,
`POST_NOTIFICATIONS`.

Отсутствие разрешения `INTERNET` означает невозможность обращения к сети
на уровне операционной системы и является технической гарантией офлайн-работы.

### 5.2. Отсутствие сетевых библиотек

Проверено содержимое release-пакета: библиотеки `okhttp`, `retrofit`, `ktor`,
`volley`, `firebase` отсутствуют.

### 5.3. Проверка нативного движка

Файл `whisper_jni.cpp` проверен на наличие сетевых вызовов:

| Проверяемый признак | Количество вхождений |
|---|---|
| `http`, `curl`, `socket`, `url`, `network` | 0 |
| Подключаемые заголовки | `jni.h`, `android/log.h`, `string`, `vector`, `whisper.h` |
| Компоненты линковки | `whisper`, `android`, `log` |

в ресурсах приложения и не требует обращения к сети.

### 6.2. Критический риск: заглушки в release-сборке

**Существо проблемы.** В ветке `feature/frontend` release-сборка содержит классы
заглушек, возвращающих заранее подготовленный текст.

**Доказательство.** Выполнена сборка `assembleRelease` и анализ содержимого пакета:

| Признак | Вхождение в `classes2.dex` |
|---|---|
| `StubAsr` | 4 |
| `StubDiarization` | 4 |
| `StubLlm` | 4 |
| `DEMO_DIALOG` | 2 |

**Причина.** В `android/app/build.gradle.kts` отсутствует разделение наборов исходников
(`src/debug`, `src/release`), а в `AppViewModel.kt:81–83` движки создаются
непосредственно как заглушки. Конфигурация сборки не влияет на состав классов.

**Последствия.** В release-сборке признак демонстрационного режима
(`usingStubs = BuildConfig.DEBUG`) принимает значение `false`, поэтому предупреждение
пользователю не отображается. При обработке произвольного аудиофайла приложение
выдаёт фиксированный текст:

```
«добрый день коллеги начнём совещание»
«давайте обсудим сроки по проекту стенографиста»
```

Указанное поведение соответствует запрету № 4 (подмена работы модели заранее
подготовленной расшифровкой) и создаёт риск дисквалификации.

**Необходимые меры.** Исключить классы заглушек из release-сборки либо обеспечить
явный отказ при отсутствии модели.

### 6.3. Замечание о готовых моделях

Официальное ТЗ (слайд 11) устанавливает: «Использование готовых моделей и библиотек
допускается». Требование о разработке модели распознавания речи «с нуля»
в документах мероприятия отсутствует.

Обоснование выбранного подхода:

| Аргумент | Содержание |
|---|---|
| Нормативный | ТЗ прямо разрешает готовые модели |
| Практический | обучение модели с нуля требует сотен часов размеченного аудио и GPU-ресурсов |
| Количественный | обучение с нуля дало бы WER порядка 0,6–0,9 против достигнутых 0,144 (потеря до 40 баллов) |
| Критериальный | критерии оценивают результат (WER, DER, RTF), а не происхождение весов |

## 9. Выводы

1. Проект приведён в соответствие с официальным ТЗ по платформе: разработано
   Android-приложение, тогда как исходное решение представляло собой веб-сервис
   с обращением к облачным API.

2. Разработаны и покрыты тестами ключевые компоненты: контракты данных, слияние
   результатов распознавания и диаризации, сериализация по схеме ТЗ, метрики качества.
   Всего 29 тестов, провалов нет.

3. Соблюдение ограничения на работу без сети подтверждено инструментально:
   разрешение `INTERNET` в пакете отсутствует.

4. Достигнутые показатели точности распознавания (WER 0,144) соответствуют целевому
   уровню и обеспечивают до 40 баллов из 100.

5. Основным незакрытым направлением является диаризация: её отсутствие
   в Android-части оставляет незакрытыми до 25 баллов из 100.

6. Обнаружен критический риск дисквалификации: наличие заглушек в release-сборке
   ветки `feature/frontend`. Требуется безотлагательное устранение.
