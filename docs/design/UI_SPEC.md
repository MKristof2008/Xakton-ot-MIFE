# Функционал и визуальный язык приложения

Макет: `docs/design/MOCKUP.html` (открыть в браузере) · скриншот: `docs/design/mockup.png`

---

## 1. Принципы

**Тихо и по делу.** Это рабочий инструмент, а не развлекательное приложение.
Никаких ярких баннеров и анимаций ради анимаций: пользователь пришёл получить текст.

**Тёмная тема по умолчанию.** Расшифровку читают подолгу, часто вечером.
Тёмный фон снижает утомляемость, а цвет остаётся за говорящими.

**Цвет — это говорящий, а не украшение.** Каждый спикер получает свой цвет,
он повторяется в аватаре, имени и полосе слева. Так видно, кто говорит, не читая имена.

**Понятный прогресс.** Обработка длится минуты. Пользователь должен видеть,
что происходит и сколько ждать, иначе он решит, что приложение зависло.

- отступы внутри карточки — 14–16, между блоками — 12–20;
- тени не используются: глубину дают границы и разница фонов.

## 3. Экраны

### 3.1 Главный — импорт

**Что видно:**
- название приложения и подпись «Локально, без интернета»;
- большая зона загрузки с пунктирной рамкой;
- список недавних записей (имя, длительность, число говорящих);
- две кнопки: «Выбрать файл» (главная) и «Записать с микрофона».

**Действия:**
- тап по зоне или кнопке → системный выбор файла (аудио);
- тап по недавней записи → сразу открывает сохранённую расшифровку;
- долгое нажатие на запись → удалить из недавних.

**Состояния:**
- пусто — вместо списка подсказка «Здесь появятся обработанные записи»;
- файл выбран — имя и размер появляются над кнопкой, кнопка становится «Обработать».

### 3.2 Обработка

**Что видно:**
- имя файла и длительность;
- круговой индикатор с процентом и оценкой оставшегося времени;
- четыре этапа со статусами: пройден (галочка), идёт (спиннер), впереди (номер);
- подпись «Полностью офлайн» — напоминание, что данные никуда не уходят.

**Этапы:**
1. Распознавание речи
2. Определение говорящих
3. Сшивка реплик
4. Восстановление пунктуации

**Действия:**
- «Отменить» — прерывает обработку, возвращает на главный;
- сворачивание в уведомление (опционально).

### 3.3 Расшифровка

**Что видно:**
- имя записи, длительность, число говорящих, RTF;
- легенда: чипы с цветом и номером каждого говорящего;
- лента реплик: цветной аватар с номером, имя, таймкод, текст.

**Действия:**
- тап по реплике → воспроизведение с этого места (когда появится плеер);
- тап по чипу говорящего → фильтр только его реплик;
- «Экспорт» → нижний лист с форматами;
- меню: переименовать говорящего, повторить обработку, удалить.

**Состояния:**
- пусто — «Речь не распознана» с кнопкой «Повторить»;
- ошибка — карточка с причиной и кнопкой «Повторить».

### 3.4 Экспорт

Нижний лист поверх расшифровки.

| Формат | Что внутри | Кому |
|---|---|---|
| JSON | структура по ТЗ: `speaker_id`, `start_ms`, `end_ms`, `text` | проверка, интеграции |
| Текст | читаемый вид с таймкодами и именами | прочитать, отправить |
| Документ | DOCX с заголовками | печать, правки |
| Поделиться | системный диалог | мессенджер, почта |

## 4. Состояния и обратная связь

| Ситуация | Поведение |
|---|---|
| Файл выбран | имя и размер над кнопкой, кнопка «Обработать» |
| Обработка идёт | прогресс по этапам, кнопка отмены |
| Успех | переход на расшифровку, лёгкая вибрация |
| Речь не найдена | «В записи не найдено речи», кнопка «Выбрать другой файл» |
| Ошибка обработки | карточка с причиной, кнопка «Повторить» |
| Нет разрешения на файл | объяснение, кнопка «Открыть настройки» |
| Модель не загружена | «Модель не найдена», ссылка на инструкцию |

## 5. Что меняется относительно текущей версии

| Сейчас | Предлагается |
|---|---|
| Один экран, всё сразу | три экрана по шагам: импорт → обработка → результат |
| Прогресс — тонкая полоса | круговой индикатор + список этапов со временем |
| Реплики — одинаковые карточки | цвет по говорящему, аватар, таймкод, легенда |
| Экспорт — две кнопки внизу | нижний лист с четырьмя форматами и пояснениями |
| Нет пустых и ошибочных состояний | описаны и показаны |
| Светлая тема Material по умолчанию | тёмная тема с собственной палитрой |

---

## 6. Что даёт на защите

- **Работоспособность и UX (10 баллов).** Три экрана вместо одного, понятный прогресс,
  читаемая расшифровка, четыре формата экспорта.
- **Защита решения (5 баллов).** Видно продуманный интерфейс, а не «слепили за ночь».
- Плюс косвенно: аккуратный UX скрывает слабости моделей — пользователь видит
  структурированный результат, а не сырой текст.

---

## 7. Порядок реализации

1. Тёмная тема и палитра в Compose (`ui/theme/`).
2. Экран импорта с зоной загрузки и списком недавних.
3. Экран обработки с круговым прогрессом и этапами.
4. Экран расшифровки с цветами говорящих и легендой.
5. Нижний лист экспорта.
6. Пустые и ошибочные состояния.

Пункты 1–2 и 4 дают основной визуальный эффект. Их делать первыми.
