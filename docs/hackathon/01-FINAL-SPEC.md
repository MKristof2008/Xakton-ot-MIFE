# Итоговое ТЗ: «Нейро-стенографист» — Nuclear IT Hack 2026

Сведено из: официальной презентации организаторов (`Хахатон Ноябрь 2026.pdf`),
описания проекта SuperAI (`neuro_stenographer_team.pdf`), файла `TZ_FOR_TEAM.md`
из репозитория. При расхождении приоритет — у официальной презентации.

---

## 1. Задача одной фразой

Разработать **Android-приложение**, которое **локально**, без интернета, преобразует
аудиозапись разговора в структурированную расшифровку: текст реплик, кто говорит,
временные метки. Результат можно посмотреть в приложении и экспортировать в файл.

---

## 2. Обязательные требования

Приложение должно:

1. работать под управлением **Android OS**;
2. использовать **локальную LLM**;
3. импортировать аудиозапись из памяти устройства;
4. преобразовывать речь в текст;
5. **автоматически** определять и разделять говорящих;
6. формировать временные метки для реплик;
7. отображать полученную расшифровку;
8. экспортировать результат в файл.

---

## 3. Жёсткие ограничения

Запрещается:

1. передавать аудиозаписи внешним сервисам для распознавания;
2. использовать облачные API для транскрибации, диаризации или обработки текста;
3. выполнять вычисления на удалённом сервере или компьютере;
4. подменять работу модели заранее подготовленной расшифровкой.

Дополнительно:

- приложение должно выполнять основную задачу **без подключения к интернету**;
- все модели должны быть **на устройстве** к моменту проверки;
- готовые модели и библиотеки использовать **разрешено**.

> **Важно.** Пункты 1–3 закрывают путь «Python + Streamlit + облачный Whisper + gpt-4o-mini».
> Именно так устроен текущий репозиторий. Это не стилистическое замечание — это риск
> обнуления результата.

---

## 4. Вход и выход

**Вход:** аудиофайл, импортированный пользователем из локального хранилища Android,
либо записанный из интерфейса приложения.

**Выход:** структурированная расшифровка в JSON:

| Поле | Тип | Смысл |
|---|---|---|
| `transcript` | array | массив реплик |
| `speaker_id` | string | идентификатор говорящего |
| `start_ms` | integer | время начала реплики, мс |
| `end_ms` | integer | время окончания реплики, мс |
| `text` | string | текст реплики |

Пример:

```json
{
  "transcript": [
    {
      "speaker_id": "speaker_1",
      "start_ms": 1250,
      "end_ms": 4380,
      "text": "Добрый день!"
    }
  ]
}
```

---

## 5. Как будут проверять

1. Эксперты устанавливают **APK**, предоставленный заранее.
2. Импортируют **три тестовые записи** диалогов.
3. Запускают транскрибацию и диаризацию.
4. Экспортируют результаты.
5. Сравнивают с эталонными расшифровками.
6. Считают **WER** (точность текста) и **RTF** (время обработки).

Все команды проверяются на одинаковых данных.

**Следствие для нас:** нужны собственные тестовые записи, приближенные к условиям проверки
(диалог, несколько говорящих, бытовая запись). Без них мы не узнаем WER до сдачи.

---

## 6. Уровни решения

**Базовый (минимум для зачёта):** работающий APK, импорт аудио, локальная LLM,
распознавание речи, автоматическая диаризация, временные метки, отображение и экспорт.

**Средний уровень (добавить):**
- предварительная обработка аудиосигнала;
- фильтрация пауз и неречевых фрагментов;
- устойчивое определение участников при смене реплик;
- восстановление пунктуации;
- отображение прогресса обработки;
- воспроизведение аудио с переходом к реплике.

**Ultra Pro Max (если останется время):**
- обработка фонового шума и некачественных записей;
- распознавание коротких реплик и перебиваний;
- обработка одновременной речи нескольких участников;
- устойчивость к разнице тембра и манеры речи;
- оптимизация потребления оперативной памяти;
- ускорение инференса за счёт аппаратных возможностей;
- редактирование и повторная обработка отдельных фрагментов.

**Стратегия:** сначала закрыть базовый целиком, потом средний по одному пункту.
Ultra — только если базовый и средний уже сдаются.

## 7. Критерии оценивания

| Критерий | Баллы | Где зарабатывается |
|---|---|---|
| Точность транскрибации (WER) | **40** | модель ASR + предобработка аудио |
| Точность диаризации (DER) | **25** | модель диаризации |
| Точность временных меток | **10** | корректный мерж сегментов |
| Скорость обработки (RTF) | **10** | квантизация, потоки, GPU/NNAPI |
| Работоспособность и UX | **10** | интерфейс, стабильность, экспорт |
| Защита решения | **5** | понимание архитектуры, ответы на вопросы |
| **Итого** | **100** | |

**Вывод по приоритетам:** 65 баллов из 100 — это ASR и диаризация. Всё остальное вместе
даёт 35. Поэтому модели и их качество важнее красивого интерфейса.

## 9. Стек и модели

Официальное ТЗ оставляет выбор за командой. Рабочий набор под Android:

| Слой | Рекомендация | Почему |
|---|---|---|
| ASR | `whisper.cpp` (ggml) или `faster-whisper` через Chaquopy | работает офлайн, есть квантизованные модели, реально запускается на телефоне |
| Модель ASR | `whisper-small` (multilingual) или `whisper-base` при нехватке памяти | small даёт заметно лучший WER на русском |
| Диаризация | `pyannote/speaker-diarization-3.1` (ONNX) или `speechbrain` embeddings + кластеризация | pyannote даёт лучший DER, но тяжелее |
| LLM | `llama.cpp` + `Gemma-2-2B` (Q4) или `Phi-3-mini` | помещаются в память телефона, есть готовые gguf |
| Пунктуация | та же локальная LLM | отдельная модель не нужна |
| UI | Kotlin + Jetpack Compose | нативный Android |

**Ограничение по железу:** телефон должен тянуть Whisper-small + Gemma-2B одновременно.
Если не тянет — модели грузятся последовательно, ASR выгружается перед LLM.

## 10. Роли в команде

Роли взяты из `neuro_stenographer_team.pdf` и переложены на Android-платформу
(в исходнике роль 4 описана как Streamlit — это не соответствует официальному ТЗ).

| № | Роль | Задачи и файлы |
|---|---|---|
| 1 | **Капитан / интегратор** (ты) | репозиторий, ветки, мерджи, `pipeline`, ревью кода, метрики, документация, подача формы |
| 2 | **ASR + диаризация** | модуль распознавания и диаризации, сбор 3–4 тестовых записей (чистая, шумная, с перебиванием), замер WER/DER |
| 3 | **LLM и промпты** | локальная LLM, пунктуация, структурирование, повторы, длинные записи (chunk/merge), QA по записи |
| 4 | **Frontend + презентация** | Android UI: импорт, прогресс, просмотр расшифровки, экспорт JSON/MD/DOCX; слайды и сценарий демо |

**Правило из ТЗ:** если людей меньше четырёх — роли 2 и 3 объединяются,
**диаризация делается последней**.

## 11. Правила работы

- каждый работает **в своей ветке** и коммитит после каждого рабочего шага;
- секреты (ключи) — только в `.env`, в репозиторий не попадают;
- `app` / UI — только интерфейс, вся логика в отдельных модулях;
- этапы: **заглушки и модули → интеграция и тест на записях → доработки → стабильность и демо**;
- пока модуль не готов, работаем на заглушках (готовый `.txt` и фиктивный JSON).
