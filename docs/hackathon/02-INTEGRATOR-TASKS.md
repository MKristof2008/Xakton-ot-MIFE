## Этап 2. Контракты и метрики (ядро моей роли)

Это то, что никто, кроме интегратора, не сделает: стыковка модулей и измерение результата.

| # | Задача | Критерий готовности | Зависимости |
|---|---|---|---|
| 2.1 | Реализовать `merge(segments, speakers)` | на вход два списка, на выходе строки `[MM:SS] Спикер N: текст`; покрыто тестом | 0.3 |
| 2.2 | Привести `transcribe()` к контракту | возвращает `list[{start, end, text}]`, а не строку | роль 2 |
| 2.3 | Реализовать `metrics.wer()` | WER считается по эталону и гипотезе, проверено на 3 примерах | — |
| 2.4 | Реализовать `metrics.rtf()` | RTF = время обработки / длительность аудио; выводится в отчёте | 2.3 |
| 2.5 | Реализовать `metrics.der()` | DER считается по эталонной разметке спикеров | роль 2 |
| 2.6 | Собрать контрольный набор | 3 записи (чистая, шумная, с перебиванием) + эталонные расшифровки в `artifacts/test-results/` | роль 2 |
| 2.7 | Прогнать замер и записать результаты | `artifacts/test-results/results.csv` заполнен реальными числами | 2.3–2.6 |

**Формат `results.csv`** (как в шаблоне организаторов):

```
file,duration_sec,processing_sec,rtf,wer,der,speakers_detected,speakers_actual,model_asr,model_llm
```
