## 3. Разрыв по контрактам ТЗ

ТЗ фиксирует четыре контракта. Выполнен один.

| Контракт | Требуется | Фактически | Разрыв |
|---|---|---|---|
| `transcribe(path)` | `list[{start, end, text}]` | `pipeline.py:73` возвращает **строку** `"[MM:SS] текст"` | формат |
| `diarize(path)` | `list[{start, end, speaker}]` | **нет функции и файла** | отсутствует |
| `merge(segments, speakers)` | строки `[MM:SS] Спикер N: текст` | **нет** | отсутствует |
| `make_minutes(transcript)` | `dict` по `MINUTES_SCHEMA` | ✓ `pipeline.py:117` | — |

Отдельно: `detect_speakers()` в `pipeline.py:138` — это **не диаризация**.
Она просит LLM угадать имена по тексту («Петя», «Анна»). Настоящая диаризация
определяет *кто когда говорит* по акустике. Это разные задачи, и 25 баллов
за DER угадывание имён не закрывает.

## 5. Дефекты, найденные при проверке

### 5.1 Проект не запускается без ключа

`client.py:12`:
```python
API_KEY = os.environ["AITUNNEL_API_KEY"]
```

Падает на импорте с `KeyError`. Проверено: `python app.py --help` не работает,
`import pipeline` не работает. Любой человек, клонировавший репозиторий,
получает краш сразу.

**Исправление:** `os.getenv()` + заглушки, как требует ТЗ.

### 5.2 `app.py` — не то, что заявлено

ТЗ роль 4: «app.py (Streamlit): загрузка, прогресс, протокол, экспорт MD/DOCX».
Фактически: CLI на `argparse` с подкомандами `minutes`/`clean`/`ask`/`speakers`/`tasks`.
`streamlit` отсутствует в зависимостях, хотя установлен в системе (1.66.1).

### 5.3 Дублированный код в `test_quality.py`

Строки 77–86: два одинаковых блока `return CheckResult(...)`.
Второй недостижим. Мёртвый код, стоит убрать.

### 5.4 Только ветка `main`

ТЗ: «каждый работает в своей ветке и коммитит после каждого рабочего шага».
Сейчас одна ветка, все коммиты в неё.

### 5.5 `README.md` — одна строка

Содержимое: `# Xakton-ot-MIFE`. Нет инструкции по установке, архитектуры,
описания моделей. По критериям отчётности это обязательные документы.

### 5.6 Расхождение документации

`TZ_FOR_TEAM.md` (добавлен коммитом `532dc0e`) описывает Android + офлайн —
то есть **правильно** по официальному ТЗ.
Но `ROADMAPS.md` и `make_pdf.py` описывают веб-пайплайн со Streamlit.

Один документ говорит одно, остальные — другое. Команда не поймёт, чему верить.

## 6. Варианты миграции

### Вариант A. Перенести логику на Android (соответствует ТЗ)

Сохраняем промпты и структуру протокола, заменяем платформу.

| Что делаем | Что получаем |
|---|---|
| `whisper.cpp` в APK вместо AITunnel Whisper | запрет №1, №2 снят |
| `pyannote` ONNX вместо угадывания имён | 25 баллов за DER |
| `llama.cpp` + Gemma-2B вместо gpt-4o-mini | запрет №2 снят |
| Kotlin UI вместо Streamlit | требование №1 выполнено |

**Плюсы:** единственный путь к зачёту по ТЗ.
**Минусы:** нужен Android-разработчик, много работы.
**Оценка:** это то, что придётся делать.

### Вариант B. Оставить Python как прототип логики

Python-пайплайн остаётся в `prototype/` как референс поведения:
как должен выглядеть протокол, как чистить текст, какие промпты.
Основной продукт — Android.

**Плюсы:** работа не выбрасывается, промпты переиспользуются.
**Минусы:** два кода надо поддерживать.

### Вариант C. Ничего не менять

**Плюсы:** нет.
**Минусы:** нарушение трёх запретов ТЗ, нет APK, нет диаризации.
При проверке эксперты ставят APK — а его нет.
