## 1. Контракты данных

Четыре функции. Подписи менять нельзя без согласования со всеми.

### `transcribe(path) → list[dict]`

Вход: путь к аудиофайлу (mp3, wav, m4a).
Выход: сегменты распознавания.

```python
[
    {"start_ms": 1250, "end_ms": 4380, "text": "Добрый день!"},
    ...
]
```

Требования: таймкоды в **миллисекундах**, не в секундах; язык русский;
пустые сегменты не возвращаются.

### `diarize(path) → list[dict]`

Вход: путь к тому же аудиофайлу.
Выход: разметка говорящих.

```python
[
    {"start_ms": 1250, "end_ms": 4380, "speaker": "speaker_1"},
    ...
]
```

Требования: количество спикеров определяется автоматически (или задаётся параметром);
интервалы могут не совпадать с ASR-сегментами — их сшивает `merge`.

### `merge(segments, speakers) → str`

Вход: результаты `transcribe` и `diarize`.
Выход: строки формата `[MM:SS] Спикер N: текст`.

```python
"[00:01] Спикер 1: Добрый день!\n[00:05] Спикер 2: Здравствуйте."
```

Правила сшивки:
- сегмент ASR получает спикера, с которым пересекается по времени больше всего;
- если пересечения нет — спикер `Спикер ?` (не выдумывать);
- номер спикера нормализуется: `speaker_1` → `Спикер 1`.

### `make_minutes(transcript) → dict`

Вход: строка от `merge`.
Выход: словарь по схеме `MINUTES_SCHEMA` (`prompts.py`): `title`, `summary`,
`topics`, `decisions`, `action_items`, `open_questions`.

Требования: только валидный JSON; таймкоды берутся из транскрипта, не выдумываются.

### Выходной JSON для организаторов

Отдельно от протокола встречи. Формат строго из ТЗ:

```json
{
  "transcript": [
    {
      "speaker_id": "speaker_1",
      "start_ms": 1250,
      "end_ms": 4380,
      "text": "Добрый день!"
    }
  ]
}
```

Порядок: по возрастанию `start_ms`. Пропусков нет.

## 2. Схема потока

```
[аудиофайл]
    │
    ├──► transcribe(path) ──► [{start_ms, end_ms, text}]
    │
    └──► diarize(path) ─────► [{start_ms, end_ms, speaker}]
                                     │
                                     ▼
                          merge(segments, speakers)
                                     │
                                     ▼
                        "[MM:SS] Спикер N: текст"
                                     │
                    ┌────────────────┴────────────────┐
                    ▼                                 ▼
            make_minutes()                    to_json() → файл
            (протокол встречи)                (формат ТЗ)
```

**Важно:** `transcribe` и `diarize` идут **параллельно** — это разные модели
и разный проход по аудио. Их можно запускать одновременно, если хватает памяти.

## 4. Ветки и порядок мержа

| Ветка | Кто | Что |
|---|---|---|
| `main` | интегратор | только стабильное, только через ревью |
| `feat/asr` | роль 2 | `asr.py`, замер WER |
| `feat/diarization` | роль 2 | `diarization.py`, замер DER |
| `feat/llm` | роль 3 | `llm.py`, `prompts.py` |
| `feat/android-ui` | роль 4 | `android/`, `app.py` |
| `feat/integration` | интегратор | `pipeline.py`, `metrics.py`, `output.py` |

Правила:
- коммит после каждого рабочего шага (требование ТЗ);
- мерж в `main` — только через ревью интегратора;
- `main` всегда собирается и проходит тесты на заглушках.

Пока модули не готовы, работаем на заглушках — это прямо предписано ТЗ.

`asr.py` (заглушка):
```python
def transcribe(path: str) -> list[dict]:
    return [{"start_ms": 0, "end_ms": 2000, "text": "заглушка"}]
```

`diarization.py` (заглушка):
```python
def diarize(path: str) -> list[dict]:
    return [{"start_ms": 0, "end_ms": 2000, "speaker": "speaker_1"}]
```

`llm.py` (заглушка):
```python
def clean_segments(segments: list[dict]) -> list[dict]:
    return segments
```

Благодаря этому `pipeline` работает end-to-end **без сети и без моделей**,
и роль 4 может делать интерфейс, не ожидая остальных.

## 6. Выбор моделей: компромиссы

| Модель | Плюсы | Минусы | Вывод |
|---|---|---|---|
| `whisper-small` | хороший WER на русском | ~500 МБ, тяжелее | **основной выбор** |
| `whisper-base` | быстрее, меньше | WER заметно хуже | fallback при нехватке памяти |
| `whisper-tiny` | очень быстрый | плохой WER на русском | только для демо скорости |
| `pyannote/3.1` | лучший DER | тяжёлый, требует токен HF | **основной выбор** |
| `speechbrain` embeddings + кластеризация | легче, офлайн | DER хуже | fallback |
| `Gemma-2-2B Q4` | помещается в телефон | качество ниже 7B | **основной выбор** |
| `Phi-3-mini Q4` | меньше, быстрее | русский слабее | альтернатива |

**Ключевое ограничение:** на телефоне одновременно Whisper-small + Gemma-2B
могут не поместиться. Решение: последовательная загрузка — ASR отработал,
выгрузился, загрузилась LLM.

## 7. Что определяет счёт

| Баллы | Что нужно | Кто отвечает |
|---|---|---|
| 40 | WER | роль 2 + предобработка аудио |
| 25 | DER | роль 2 |
| 10 | точность таймкодов | интегратор (`merge`) |
| 10 | RTF | роль 2 (квантизация) + интегратор (профилирование) |
| 10 | UX и работоспособность | роль 4 |
| 5 | защита решения | интегратор (документация) |

Интегратор напрямую отвечает за **15 баллов** (таймкоды + документация)
и косвенно — за то, чтобы остальные 85 не потерялись на стыках.
