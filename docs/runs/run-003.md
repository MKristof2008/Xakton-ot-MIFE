# Прогон 003 — ggml-tiny (коммит 545a3fb)

## Параметры
- Модель: ggml-tiny.bin (~78 МБ), whisper.cpp JNI, flash_attn, 8 потоков
- Устройство: Samsung SM-S938B, CPU
- Запись: 25 600 мс (живая речь с микрофона телефона), 00:28:27

## Замеры
- Инференс: 98 457 мс → **RTF = 3.85** (лучше base в 1.5 раза, цель <1 не достигнута)

1 реплика [0..25600 мс] на всю запись.

## Разбор ошибок
1. **E1 Скорость**: RTF 3.85 — tiny в 4.3 раза быстрее small, но до цели <1
   ещё ×3.9. whisper.cpp на CPU телефона упёрся.
2. **E3 Галлюцинации — катастрофа**: текст почти полностью бессмысленный
   («Шпакышной», «педичайный», «подпон»). Повторы «как лет, как лет, как лет»
   и «громкий громкий громкий» — классическая петля tiny на шуме/тишине.
   Качество недопустимое: tiny на русском живой речи не тянет.
3. **E2 Потеря речи / сегментация**: снова один сегмент на всю запись —
   whisper не дробит на реплики без VAD; таймкоды бесполезны (0–25600).
4. **E5/E6**: спикеров и точных границ нет по той же причине.

## Вывод — ПЕРЕСМОТРЕН (замечание капитана)
Прогоны 001–003 — на разных записях, без эталона и WER: сравнение моделей
недействительно. Замеры делались на assembleDebug (нативный C++ без полной
оптимизации) — RTF может быть завышен. Утверждения о «потере речи» и
«галлюцинациях» — впечатления без эталона, не доказательство.
До выводов нужно: Release-сборка (CMAKE_BUILD_TYPE=Release, -O3, NEON),
единый набор из 3 записей с ручными эталонами, ≥3 повтора, медиана, WER/DER
по эталону. Решение о стеке (whisper.cpp vs sherpa-onnx) — только после
этих замеров.
