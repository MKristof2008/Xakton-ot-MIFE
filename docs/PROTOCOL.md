# Контракты данных

Спецификация интерфейсов между модулями. Подписи менять нельзя без согласования:
на них опираются параллельно разрабатываемые части.

## 1. Распознавание речи

```kotlin
suspend fun transcribe(audioPath: String): List<AsrSegment>

data class AsrSegment(
    val startMs: Long,
    val endMs: Long,
    val text: String,
)
```

**Вход:** путь к аудиофайлу (mp3, wav, m4a, ogg).
**Выход:** список сегментов, упорядоченных по времени.
**Требования:**
- таймкоды в **миллисекундах**;
- пустые сегменты не возвращаются;
- язык русский.

## 2. Определение говорящих

```kotlin
suspend fun diarize(
    audioPath: String,
    expectedSpeakers: Int? = null,
): List<SpeakerSegment>

data class SpeakerSegment(
    val startMs: Long,
    val endMs: Long,
    val speaker: String,
)
```

**Вход:** путь к тому же аудиофайлу; ожидаемое число говорящих (null — автоопределение).
**Выход:** интервалы речи с идентификатором говорящего.
**Требования:**
- интервалы могут не совпадать с сегментами распознавания — их сшивает `merge`;
- идентификатор стабилен в пределах одной записи;
- формат идентификатора произвольный (`speaker_1`, `SPEAKER_00`), нормализуется при сшивке.

## 3. Сшивка

```kotlin
fun merge(
    segments: List<AsrSegment>,
    speakers: List<SpeakerSegment>,
): List<TranscriptLine>
```

**Правила:**
1. Сегмент распознавания получает говорящего с максимальным пересечением по времени.
2. Если пересечения нет — `speaker_unknown`. Говорящий не выдумывается.
3. Идентификаторы нормализуются к виду `speaker_N`, нумерация — по первому появлению в записи.
4. Сегменты с пустым текстом отбрасываются.
5. Результат упорядочен по возрастанию `startMs`.

**Формат для языковой модели:**
```
[MM:SS] Спикер N: текст
```

## 4. Языковая модель

```kotlin
suspend fun clean(text: String): String
```

**Вход:** текст реплики.
**Выход:** текст с восстановленной пунктуацией и регистром.
**Требования:**
- не перефразировать;
- не сокращать;
- не добавлять смысл;
- при ошибке вернуть исходный текст (обработка не должна ломать пайплайн).

## 5. Выходной JSON

Формат строго по техническому заданию:

```json
{
  "transcript": [
    {
      "speaker_id": "speaker_1",
      "start_ms": 1250,
      "end_ms": 4380,
      "text": "Добрый день!"
    }
  ]
}
```

**Требования:**
- ровно четыре поля на реплику, лишних нет;
- `speaker_id` — строка, `start_ms`/`end_ms` — целые числа, `text` — строка;
- порядок — по возрастанию `start_ms`;
- кодировка UTF-8.

## 6. Метрики

```kotlin
fun wer(reference: String, hypothesis: String): Double
fun der(reference: List<SpeakerSegment>, hypothesis: List<SpeakerSegment>): Double
fun rtf(audioDurationSec: Double, processingTimeSec: Double): Double
```

**WER** — доля ошибочных слов: `(замены + удаления + вставки) / слов в эталоне`.
Сравнение регистронезависимое, пунктуация отбрасывается.

**DER** — доля времени, размеченного неверно: пропуски речи + ложные срабатывания +
путаница говорящих, делённые на общую длительность эталонной речи.

**RTF** — отношение времени обработки к длительности аудио. Меньше 1.0 — быстрее
реального времени.

## Порядок вызовов

```
transcribe ─┐
            ├─→ merge ─→ clean ─→ toJson
diarize   ──┘
```

`transcribe` и `diarize` независимы и могут выполняться параллельно при достатке памяти.
