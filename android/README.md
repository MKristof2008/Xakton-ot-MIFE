# Нейро-стенографист — Android-приложение

Локальная расшифровка диалогов: речь → текст, кто говорит, таймкоды, экспорт JSON.
**Всё считается на устройстве, сеть не используется.**

| | |
|---|---|
| Пакет | `ru.mifi.stenograf` |
| minSdk / targetSdk | 26 / 34 |
| ABI | `arm64-v8a` |
| Размер APK | ~235 МБ (модели внутри, чтобы работало без сети сразу после установки) |
| Разрешения | **ни одного сетевого** — `INTERNET` и `ACCESS_NETWORK_STATE` удалены из манифеста |

## Сборка

```bash
cd android
./scripts/build.sh          # скачает библиотеки (~70 МБ) и модели (~200 МБ), прогонит тесты, соберёт APK
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Или по шагам:

```bash
./scripts/fetch_libs.sh     # sherpa-onnx.aar + onnxruntime-genai.aar -> app/libs
./scripts/fetch_models.sh   # whisper-base int8 + pyannote-seg + 3D-Speaker -> assets
./gradlew testDebugUnitTest assembleDebug
```

Требуется JDK 17+ и Android SDK (platform 34, build-tools 34.0.0). Сборка проверена:
Gradle 8.7, AGP 8.5.2, Kotlin 2.0.21.

## Пайплайн

```
аудиофайл (SAF, content://)
   ↓ AudioDecoder      MediaCodec/MediaExtractor → PCM float32 16 кГц моно
   ↓ AsrEngine         sherpa-onnx + Whisper base int8, language=ru, окна 20 с / перекрытие 2 с
   ↓ Diarizer          sherpa-onnx: pyannote segmentation-3.0 + 3D-Speaker ERes2Net + кластеризация
   ↓ Merge             разрезание сегментов по смене говорящего, склейка, нумерация speaker_N
   ↓ LlmPost           ONNX Runtime GenAI: пунктуация и регистр (опционально, с защитой от галлюцинаций)
   ↓ HexJson           JSON по схеме ТЗ + валидатор
```

| Модуль | Файл | Что делает |
|---|---|---|
| Декодер | `audio/AudioDecoder.kt` | любой формат → 16 кГц моно, ресемплинг, нормализация |
| ASR | `asr/AsrEngine.kt` | распознавание, таймкоды от начала файла |
| Диаризация | `diar/Diarizer.kt` | сегментация + эмбеддинги + кластеризация |
| Слияние | `output/Merge.kt` | порт `diarization.py::_best_speaker`, `output.py::merge_adjacent`, `normalize_speakers` |
| Экспорт | `output/HexJson.kt` | JSON + валидатор (порт `output.py::validate_hex`) |
| Локальная LLM | `llm/LlmPost.kt` | пунктуация; откат при потере слов или росте длины > 30 % |
| UI | `ui/*.kt` | импорт → прогресс → результат → экспорт |

## Модели

| Модель | Файл в `assets/models` | Размер | Лицензия |
|---|---|---|---|
| Whisper small int8 (multilingual) | `asr/whisper-small-*.onnx` | 374 МБ | MIT |
| Whisper base int8 (запасной) | `asr/whisper-base-*.onnx` | 152 МБ | MIT |
| pyannote segmentation 3.0 | `diar/segmentation-3.0.onnx` | 5.7 МБ | MIT |
| 3D-Speaker ERes2Net | `diar/3dspeaker_eres2net.onnx` | 38 МБ | Apache-2.0 |

Модели не хранятся в git — их скачивает `scripts/fetch_models.sh`.
В собранном APK они лежат в assets и распаковываются при первом запуске в `filesDir/models`.

**Локальная LLM** подключается опционально: положите модель ONNX Runtime GenAI
(`genai_config.json` + `*.onnx` + `*.onnx.data`) в `assets/models/llm/phi3-mini/`.
Без неё работает детерминированный пунктуатор — пайплайн не падает.

## Почему sherpa-onnx, а не whisper.cpp

| | sherpa-onnx (выбрано) | whisper.cpp |
|---|---|---|
| Готовый AAR для Android | ✅ | ❌ нужна своя сборка NDK + исходники в репозитории |
| Диаризация из коробки | ✅ pyannote + эмбеддинги + кластеризация | ❌ писать самому |
| Tаймкоды по токенам | ✅ | ✅ |
| Время до рабочего APK | часы | дни |

Отдельная JNI-обвязка над whisper.cpp осталась в `docs/legacy-android-stub/` как запасной путь,
если sherpa-onnx на конкретном устройстве покажет плохой WER.



## Выбор модели ASR: замеры на устройстве

Одна и та же шумная запись (96 с, белый шум 10 дБ, 2 говорящих):

| Модель | Размер | WER | Время ASR | Итоговый RTF | Качество текста |
|---|---|---|---|---|---|
| whisper-base int8 | 152 МБ | 0.346 | 23 с | 0.61 | петли декодера: «дыхки, лым, как гей, лы» |
| whisper-small int8 | 374 МБ | 0.154 | 68 с | ~1.08 | читаемо, но слова путаются на разговорной лексике |
| **zipformer-ru int8** | **71 МБ** | **0.054** | **6 с** | **0.43** | **корректно, включая разговорные слова** |

Почему zipformer-ru лучше Whisper для этой задачи:
- обучен ТОЛЬКО на русском — разговорная лексика и мат в словаре, а не
  «угадываются» через английский;
- неавторегрессионный трансдьюсер: нет петель и повторяющихся фраз;
- в 10 раз быстрее на том же устройстве, в 5 раз меньше по размеру.

Цена: не ставит пунктуацию (её восстанавливает Grammar.kt правилами) и
может нормализовать числа словами.


## Запись голоса прямо в приложении

Кнопка «Записать голос» рядом с импортом файла. Формат голосового сообщения:
круглая кнопка, пульсирующие кольца по уровню сигнала, таймер. Пишем сразу
в WAV 16 кГц моно (AudioRecord + RIFF-заголовок), поэтому декодирование не нужно.

Найдено и исправлено при проверке на устройстве:
-  пропал из манифеста при чистке сетевых разрешений;
-  не открывает сырой PCM → «Failed to instantiate extractor».
  Добавлен собственный разбор WAV (PCM 8/16/24/32 и float32, любой канал/частота);
- файл копировался раньше, чем дописывался RIFF-заголовок: первые 44 байта
  оставались нулями, и WAV не открывался. Теперь ждём  —
  в нём убрана проверка , из-за которой ожидание не работало вовсе.


## Разделение голосов в живой записи

Диаризация работает и на записи с микрофона — но с двумя оговорками:

1. Раньше экран записи жёстко передавал «1 говорящий», поэтому разделение
   было отключено. Теперь есть переключатель «Один / Несколько».
2. Источник записи — , а не :
   последний включает агрессивное шумоподавление и подавление эха, которое
   вырезает второй голос. MIC пишет оба.

Порог кластеризации подобран замером на двух записях:

| Порог | dialog_2spk (DER) | Говорящих | dialog_3spk |
|---|---|---|---|
| 0.50 | 0.347 | 3 вместо 2 | — |
| **0.75** | **0.243** | **2 верно** | **3 верно** |
| 0.85 | 0.243 | 2 верно | — |

Оставлено 0.75: тот же DER, но ниже риск склеить двух разных людей с похожим
тембром. Один микрофон физически ограничивает задачу: перебивания и наложение
речи разделяются хуже, чем при записи с двух устройств или стерео.

## Устойчивость к шуму (замерено на устройстве)

| Условие (SNR 10 дБ, если не указано) | WER | DER | RTF |
|---|---|---|---|
| чистая запись | 0.246 | 0.252 | 0.67 |
| белый шум, 20 дБ | 0.246 | 0.189 | 0.60 |
| белый шум, 10 дБ | 0.385 | 0.190 | 0.61 |
| розовый шум | 0.277 | 0.251 | 0.74 |
| гул 50/100 Гц | 0.223 | 0.245 | 0.63 |
| babble (говорят вокруг) | 0.438 | 0.214 | 0.78 |

Выводы:
- **Диаризация к шуму устойчива**: DER не растёт, на белом шуме даже падает
  (шум маскирует паузы, границы реплик становятся чище).
- **Распознавание деградирует на широкополосном шуме**: 25 % -> 38-44 %.
  Гул сети почти не влияет (22 %): модель к нему устойчива.
- Худший случай — babble, когда вокруг говорят другие люди.

Шумоподавление (audio/Denoise.kt) реализовано, но в пайплайне выключено:
замерено, что спектральное вычитание поднимает SNR с 13.5 до 13.7 дБ
и стоит минуты на 96 с записи. Включать только вместе с нативной реализацией.

## Ограничения

1. Только `arm64-v8a` — эмулятор x86 не подойдёт, нужен реальный телефон.
2. Whisper `small` выбран по замерам: WER на шумной записи 0.154 против 0.346 у `base`.
   Цена — ASR 68 с вместо 23 с на 96 с аудио и +210 МБ в APK.
3. Диаризация чувствительна к числу говорящих: авторежим ошибается на 4+; если известно — указывайте вручную.
4. Модель 3D-Speaker обучена на китайском/английском; на русской речи работает, но уступает pyannote 3.1 на ПК.
5. Первый запуск распаковывает ~200 МБ из assets — 10–30 секунд.
6. Длинные записи (> 30 мин) держат PCM в памяти: на 4 ГБ RAM это ~1 ГБ на час аудио.
