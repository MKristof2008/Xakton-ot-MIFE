# ТЗ для команды: «Нейро-стенографист»

Источник: официальная презентация организаторов Nuclear IT Hack 2026
(`Хахатон Ноябрь 2026.pdf`). При расхождении с любыми другими документами
приоритет — у презентации.

---

## Задача

Разработать **Android-приложение**, которое локально преобразует аудиозаписи разговоров
в текст, автоматически определяя говорящих и разделяя их реплики. Результат —
структурированная расшифровка с участниками и временными метками, доступная для просмотра
и экспорта в файл. Все этапы обработки выполняются на устройстве.

---

## Обязательные требования

1. Работа под управлением Android OS.
2. Использование локальной LLM.
3. Импорт аудиозаписи из памяти устройства.
4. Преобразование речи в текст.
5. Автоматическое определение и разделение говорящих.
6. Формирование временных меток для реплик.
7. Отображение полученной расшифровки.
8. Экспорт результата в файл.

---

## Запрещается

1. Передавать аудиозаписи внешним сервисам для распознавания.
2. Использовать облачные API для транскрибации, диаризации или обработки текста.
3. Выполнять вычисления на удалённом сервере или компьютере.
4. Подменять работу модели заранее подготовленной расшифровкой.

Приложение должно выполнять основную задачу без подключения к интернету.
Все модели должны быть доступны на устройстве к моменту проверки.
Использование готовых моделей и библиотек допускается.

---

## Вход и выход

**Вход:** аудиофайл, импортированный из локального хранилища, либо записанный
из интерфейса приложения.

**Выход:** JSON строго такого вида:

```json
{
  "transcript": [
    {
      "speaker_id": "speaker_1",
      "start_ms": 1250,
      "end_ms": 4380,
      "text": "Добрый день!"
    }
  ]
}
```

| Поле | Тип | Смысл |
|---|---|---|
| `speaker_id` | string | идентификатор говорящего |
| `start_ms` | integer | начало реплики, мс |
| `end_ms` | integer | конец реплики, мс |
| `text` | string | текст реплики |

## Критерии оценивания

| Критерий | Баллы |
|---|---|
| Точность транскрибации (WER) | 40 |
| Точность диаризации (DER) | 25 |
| Точность временных меток | 10 |
| Скорость обработки (RTF) | 10 |
| Работоспособность и UX | 10 |
| Защита решения | 5 |
| **Итого** | **100** |

**Вывод:** 65 баллов из 100 — это качество моделей распознавания и диаризации.
Интерфейс важен, но он не вытянет решение, если WER и DER плохие.

## Выбранные модели (фиксируем, меняем только по согласованию)

| Компонент | Модель | Почему | Статус |
|---|---|---|---|
| ASR (русская речь) | **faster-whisper, размер `small`** (CTranslate2, int8) | лучший баланс WER/скорость для CPU и Android-порта; `tiny` даёт WER 0.35 — неприемлемо | замерено на 20 записях VoxForge RU |
| ASR запасной вариант | faster-whisper `base` | если small не влезет в устройство по памяти/RTF | готов |
| Диаризация | **pyannote/speaker-diarization-3.1** | стандарт для DER, есть автоопределение числа спикеров | установлен, нужен HF-токен для скачивания |
| Диаризация запасной | speechbrain ECAPA + кластеризация | если pyannote не портировать на Android | не начат |
| LLM (пунктуация/очистка) | **Gemma-2-2B (GGUF, llama.cpp)** или Phi-3-mini-q4 | требование ТЗ «локальная LLM», влезает в телефон | выбрать и замерить |
| Выходной JSON | `output.py` / `TranscriptJson.kt` | схема HEX зафиксирована выше, валидатор готов | готово |

**Тестовые записи:** `artifacts/test-audio/` — 20 русских wav (VoxForge) с эталонными
транскриптами; замер — `evaluate_wer.py`. Для диаризации нужны записи с 2–3 спикерами
(записать свои 3–5 коротких мини-совещаний).

## Контракты данных (фиксируются в первый час)

```kotlin
transcribe(path: String): List<{startMs, endMs, text}>
diarize(path: String, expectedSpeakers: Int?): List<{startMs, endMs, speaker}>
merge(segments, speakers): List<{speakerId, startMs, endMs, text}>
clean(text: String): String
```

Пока модуль не готов — используется заглушка (фиктивный список и фиктивный JSON).
Это не временная мера, а требование: без заглушек параллельная работа невозможна.

Подробная спецификация — `docs/PROTOCOL.md`.

## Роли

| № | Роль | Задачи и файлы |
|---|---|---|
| 1 | Капитан / интегратор | репозиторий, ветки, мерджи, контракты, метрики, документация, подача формы |
| 2 | ASR + диаризация | модель распознавания, модель диаризации, сбор контрольных записей, замер WER и DER |
| 3 | LLM и промпты | локальная языковая модель, пунктуация, длинные записи, обработка ошибок |
| 4 | Frontend + презентация | Android-интерфейс, экспорт, слайды и сценарий демо |

Если людей меньше четырёх — роли 2 и 3 объединяются, **диаризация делается последней**.

## Правила работы

- каждый работает в своей ветке и коммитит после каждого рабочего шага;
- секреты — только в `.env`, в репозиторий не попадают;
- интерфейс — только интерфейс, логика в отдельных модулях;
- этапы: **заглушки и модули → интеграция и тест на записях → доработки → стабильность и демо**.

## Что делать нельзя (по опыту нашего же репозитория)

| Антипаттерн | Почему |
|---|---|
| Транскрибация через облачный API | запрет №1 и №2, дисквалификация |
| LLM по сети | запрет №2 |
| Веб-приложение вместо APK | не выполнено требование №1 |
| «Диаризация» угадыванием имён по тексту | это не диаризация, 25 баллов не закрываются |
| Основной продукт на Python | не запускается на Android |
