## 1. Нейро-стенографист (Hex.team) — наш пайплайн

**Цель:** аудио → транскрипт → протокол с решениями и поручениями.

### Критерии из документов
- Критерии приёмки согласованы заранее (ИИ-агенты, слайд 25)
- Версии сравниваются на одном контрольном наборе (Видеоаналитика, правило 4)
- Не чёрный ящик: видно, кто и по каким правилам решил (Баланс-Платформа)

### Этапы
- [x] Интеграция с AITunnel API (gpt-4o-mini + Whisper)
- [x] Промпты: очистка ASR, протокол, map-reduce, QA, спикеры
- [x] CLI: minutes / clean / ask / speakers / tasks
- [ ] Контрольный набор: 3-5 реальных транскриптов встреч
- [ ] Метрики качества: точность решений, полнота поручений, null-безопасность
- [ ] Версионирование промптов (git-теги: v0.1, v0.2...)
- [ ] Тест на реальном аудиофайле (mp3/wav)

### Критерии приёмки
1. Протокол содержит все явные решения из транскрипта (recall = 1.0 по контрольному набору)
2. Поручения только при явном обязательстве (precision по action_items ≥ 0.9)
3. Таймкоды сохранены из источника, не выдуманы
4. QA отвечает «В записи этого нет» только когда ответа действительно нет
5. Имена спикеров — null при отсутствии явного упоминания

### Метрики
- Время обработки 1 часа записи ≤ 5 минут
- Стоимость одного протокола ≤ 50 руб. (gpt-4o-mini)

## 2. Баланс-Платформа (Артём Карпов)

**Цель:** реализация бизнес-процессов на движке компании.

### Критерии из документа
- SQL или Python, статистика, внимание к деталям
- AI-агент собирает процесс через MCP, часы вместо недель
- Визуальный редактор, таблицы решений, прозрачность

### Этапы
- [ ] Изучить API платформы и MCP-сервер
- [ ] Собрать тестовый бизнес-процесс (кредитная заявка)
- [ ] Написать AI-агента для генерации процесса из задачи на естественном языке
- [ ] Тестирование и откат без простоя

### Критерии приёмки
1. Процесс собирается AI-агентом и виден в редакторе
2. Решение принимается за секунды на реальных данных
3. Полный аудит: кто, что и по каким правилам решил

## 3. Видеоаналитика в эксплуатации (Данила Дементьев)

**Цель:** снизить ложные тревоги без роста пропусков.

### Критерии из документа
- Метрики только с условиями применимости (ракурс, освещение, зоны)
- Precision/recall под сценарий, ложные тревоги за смену
- Систематический сбор hard negative
- Версии на одном контрольном наборе

### Этапы
- [ ] Зафиксировать условия применимости для сценария
- [ ] Базовые метрики: precision, recall, ложные тревоги/смену, задержка
- [ ] Логика событий после модели: подтверждение на кадрах, анализ трека
- [ ] Сбор hard negative → дообучение → повторная оценка

### Критерии приёмки
1. Ложные тревоги ≤ N за смену (N согласовано)
2. Пропуски не выросли относительно baseline
3. Задержка первого уведомления ≤ T секунд

## 4. ИИ-агенты (интенсив)

**Цель:** проверить, где агент действительно нужен.

### Критерии из документа
- Сравнить агента с простым решением (baseline)
- Критерии успеха до запуска: цель, ограничения, инварианты
- Больше агентов ≠ лучше: измерять пользу vs стоимость/задержку
- 4 вопроса: автономность? наблюдения? приёмка? окупаемость?

### Этапы
- [ ] Выбрать задачу (например, генерация SQL из вопроса)
- [ ] Простое решение: шаблоны/правила
- [ ] AI-агент на той же задаче
- [ ] Сравнение: качество, стоимость, задержка

### Критерии приёмки
1. Агент лучше baseline на заранее записанных метриках
2. Стоимость и задержка окупаются выигрышем в качестве
